# 企业托管应用内嵌设计

## Context

应用中心及应用广场运行在企业网页的原生视图内。托管应用卡片使用 `window.open('/apps/{slug}')` 进入企业应用代理路径。现有企业网页控制器处理弹出请求，并维护当前账号的网页会话及续期。

## Goals / Non-Goals

在同一主窗口运行托管应用。沿用当前已登录账号并保留回到原目录的入口。沿用企业网页和代理的产品能力，以及 Harness 提供的布局扩展点。

## Decisions

1. **在企业网页的弹出请求识别应用。** 主进程仅从当前已连接账号的可见应用中心或应用广场识别同源的 `/apps/{slug}` 启动链接。按企业代理约定校验 slug，再使用固定应用根路径创建视图。服务端继续检查应用是否存在及用户是否有权使用。
2. **独立承载应用内容。** 主进程为应用创建沙箱 `WebContentsView` 和独立内存 Session。应用页面关闭 Node 集成，启用上下文隔离和 Web 安全，且没有桌面 preload。应用视图只访问所属应用代理路径，主进程限制跳转、新窗口和权限请求。
3. **在请求边界复用企业身份。** 企业网页继续负责会话交换和续期。主进程检查视图归属、企业账号及有效期，只为指定应用代理路径内的请求附带企业会话 Cookie。应用 Session 的 Cookie 存储不写入该凭据。退出、账号切换、关闭主窗口或关闭应用时，销毁对应的应用视图并清理其浏览状态，旧请求无法继续获取凭据。
4. **与桌面内容区协同呈现。** 现有内容插槽以当前窗口、标题栏控件、宿主侧栏和固定 DS Bot 侧栏确定应用边界，并在返回工具栏下方放置原生视图。浮动 Bot 抽屉、宿主弹层、设置和恢复页打开时应用视图让出内容区。远程设置继续按其现有边界呈现。通过工具栏直接返回时，恢复原目录文档和焦点。切换到 Work、企业会话或其他企业页面时释放应用视图，由目标页面接管导航。
5. **为应用失败保留恢复入口。** 视图加载失败、超时、失去渲染进程或请求发现会话过期时进入失败状态，只显示可恢复操作。重试在账号会话可用时创建新视图。日志记录失败阶段，避免输出凭据或完整 URL。

## Risks / Trade-offs

- 托管应用依赖平台的应用代理和所属路径。将资源或后续跳转配置在其他地址会被内容视图拦截。
- 保留列表、筛选和滚动位置适用于直接从应用返回。远程设置继续复用企业网页原有路由切换和恢复机制。
