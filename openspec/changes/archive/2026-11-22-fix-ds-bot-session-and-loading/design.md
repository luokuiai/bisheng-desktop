# 首次发送与模块加载修复设计

## Context

BISHENG 在 Harness `0.2.1-rc.2` 的会话输入通道中增加了发送前模型校验。该校验通过会话模型目录获取当前可用模型。Cordis 在调用方作用域解析 `remote.session`。ds-bot 替换模型选择器后，发送校验可能是第一次创建模型目录，因此会触发调用方缺少依赖声明的问题。

企业市场根组合把插件入口解析为实际模块 URL。同一代 ds-bot 的两个后端入口分别对应不同 URL，但都由同一份包声明提供客户端脚本。客户端模块发现原先按入口 URL 区分来源。

## Goals / Non-Goals

修复范围为普通会话的发送前校验和客户端模块发现。后端导入和客户端发现继续从实际 Loader 解析结果出发，企业授权和普通 Profile 均沿用现有服务和生命周期。

## Decisions

1. **在会话插件的作用域声明依赖。** 在现有 `dsh-client-ui-conversation` 补丁中声明 `remote.session`。Cordis 管理该服务的可用性，原有模型校验、取消和提交顺序继续沿用。
2. **以实际包目录识别安装来源。** 客户端模块发现复用 Loader 的解析基准找到包的 manifest，再用所在的物理目录归并记录。后端入口仍逐一跟踪启停，客户端图按包目录合并。同名包来自不同物理目录时，保留来源冲突和对应的 Loader 信息。
3. **使用现有补丁重放流程。** 两处调整记录在 `0.2.1-rc.2` 的既有补丁中，依赖安装时重放。升级 Harness 时分别核对发送前校验和包目录合并契约，上游提供等价行为后移除对应补丁。

## Risks / Trade-offs

- **模型目录路径依赖上游作用域查找。** 用实际 Cordis、会话 Remote 与发送通道验证尚未打开模型选择器的首次提交。
- **同名插件可能真实重复安装。** 使用实际包目录区分来源，覆盖同目录多入口与不同目录冲突。日志保留对应加载入口。
